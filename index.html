Automatisches Researchsystem

Das System hilft beim Sammeln, Ordnen und Prüfen von Research-Material. Es legt Quellen, Aussagen, Dossiers und Aufgaben im Vault ab.

Einrichtung Prompt kopieren

Überblick

Das Researchsystem hat Eingaben und Ausgaben.

Eingaben

  • Forschungsfrage
  • Korpus mit Quellen und Notizen
  • Suchachsen und Ausschlüsse
  • gewünschtes Ausgabeformat

Ausgaben

  • Quellenkarten
  • Claim-Karten
  • Review-Notizen
  • Dossier-Updates

Einrichtung

So wird der Vault angelegt.

1. Ordner anlegen

Lege einen Vault oder Projektordner an. Nutze diese Struktur:

00_Inbox
neue Links, PDFs, Notizen, Screenshots, Gesprächsnotizen
01_Quellen
Source Cards mit Autor, Datum, URL, Fundstelle und Quellentyp
02_Claims
eine Aussage pro Datei mit Belegstelle und Status
03_Dossiers
Themen, Begriffe, offene Fragen, Synthesen
04_Review
Gegenbelege, Evidenzgrenzen, Prüffragen
05_Output
Texte, Vorlagen, Berichte, Lehrmaterial

2. Dateien vorbereiten

Lege diese Startdateien an:

  • README.md mit Zweck, Thema und Zuständigkeit
  • AGENT.md mit Rollen, Regeln und Ausgabeformaten
  • prompts/research_lauf.md
  • prompts/source_card.md
  • prompts/claim_card.md
  • prompts/review.md

3. Ersten Lauf starten

Lege drei Quellen in 00_Inbox. Starte den Prompt research_lauf.md. Prüfe danach, ob Quellenkarten, Claim-Karten und Dossier-Update angelegt wurden.

Bauteile

Das System hat sechs feste Ebenen.

Minimaler Aufbau

Rohmaterial, Quellen, Claims, Reviews, Dossiers und Outputs liegen getrennt.

Agenten, Skills und Prompts steuern Arbeitsschritte. Evidenz wird mit Quellen verbunden.

01

Inbox und Rohmaterial

PDFs, Links, Exporte, Notizen, Gespräche, Screenshots und erste Fragen.

02

Source Cards

Autor, Datum, Herkunft, Quellentyp, Interessenlage, Claims und offene Fragen.

03

Claim Cards

Eine prüfbare Aussage pro Karte, mit Quelle, Belegstelle, Grenze und Status.

04

Review

Gegenbelege, Evidenzgrenzen, Zitationsketten, Unsicherheit und fachliche Prüfung.

05

Dossiers

Lebende Synthesen zu Themen, Begriffen, Mustern, offenen Fragen und Gegenpositionen.

06

Outputs

Intranet-Texte, Lehrmaterial, Reports, Vortragsnotizen und Publikationen.

Tools

Diese Tools werden verbunden.

Basis

Ein Vault braucht Speicherort, Schreibwerkzeug, Quellenverwaltung und Agentenzugriff.

Speicherort
Google Drive, OneDrive, GitHub oder lokaler Projektordner
Schreibwerkzeug
Obsidian, Notion, Markdown-Ordner oder GitHub Pages
Quellenverwaltung
Zotero, Literaturdatenbank, PDF-Ordner oder Linkliste
Agentenzugriff
Codex, Claude Code, Cursor oder ein anderer Agent mit Dateizugriff
01

Vault verbinden

Der Agent braucht Lese- und Schreibzugriff auf den Vault-Ordner.

02

Quellenordner festlegen

PDFs, Links und Exporte liegen in 00_Inbox oder 01_Quellen.

03

Prompt-Ordner anlegen

Alle wiederkehrenden Anweisungen liegen in prompts/.

04

Run Log anlegen

Jeder Lauf bekommt Datum, Eingaben, erzeugte Dateien und offene Aufgaben.

Zwischenstände

Jeder Schritt hat ein eigenes Ziel.

Frage klären

Der Auftrag begrenzt Thema, Korpus, Zielgruppe und Ausschlüsse.

Status: scoping

Status

Jede Karte bekommt einen Arbeitsstatus.

Drei Ebenen

Signal
Was wurde gefunden oder wiederholt beobachtet?
Interpretation
Welche Deutung wird daraus abgeleitet?
Evidenz
Was trägt die Quelle tatsächlich?

Statusleiter

  1. inbox
  2. scoping
  3. signal
  4. evidence-linked
  5. evidence-checked
  6. claim-ready

Freigabe

Ein Claim erhält den Status claim-ready, wenn Quelle, Belegstelle, Grenze, Gegenprüfung und Review-Entscheidung dokumentiert sind.

Agenten, Skills, Prompts

Diese Prompt-Dateien steuern den Lauf.

prompts/research_lauf.md

Nutze diesen Prompt für den ersten vollständigen Lauf:

Aufgabe
Lies 00_Inbox. Erstelle Source Cards, Claim Cards, Review Note und Dossier Update.
Regel
Trenne Fund, Deutung und Beleg. Jede Aussage bekommt Quelle und Status.
Ausgabe
Schreibe neue Dateien in 01_Quellen, 02_Claims, 03_Dossiers und 04_Review.
Log
Schreibe Datum, Eingaben, Ausgaben und offene Aufgaben in 04_Review/run_log.md.
01

source_card.md

Erstelle eine Quellenkarte mit Titel, Autor, Datum, URL, Quellentyp, Kerninhalt und möglichen Claims.

02

claim_card.md

Formuliere eine einzelne Aussage. Ergänze Belegstelle, Evidenztyp, Grenze, Status und verknüpfte Quelle.

03

review.md

Prüfe Claims auf Beleg, Gegenbeleg, Evidenzgrenze, Zitationskette und offene Frage.

04

dossier_update.md

Ordne geprüfte Claims in ein Dossier ein. Ergänze Begriffe, Links, offene Fragen und nächste Schritte.

05

weekly_refresh.md

Suche neue Quellen, aktualisiere offene Fragen und schreibe ein Run Log.

06

output_draft.md

Erstelle einen Entwurf aus Claims mit Status, Dossiers und Quellenkarten.

MCP

Wiki-Schicht

speichert Wissen als Quellen, Claims, Konzepte und Dossiers.

Prompt zum Anlegen des Vaults

Ziel:
Lege ein automatisches Researchsystem als Vault an.

Projekt:
[Name des Forschungs- oder Intranet-Themas]

[Google Drive / OneDrive / GitHub / lokaler Ordner]

Tools:
- Schreibwerkzeug: [Obsidian / Notion / Markdown-Ordner]
- Quellenverwaltung: [Zotero / PDF-Ordner / Linkliste]
- Agent: [Codex / Claude Code / Cursor]
- Ausgabeort: [Intranet / Bericht / Lehrmaterial / Dissertation]

Ordner:
1. Erstelle 00_Inbox.
2. Erstelle 01_Quellen.
3. Erstelle 02_Claims.
4. Erstelle 03_Dossiers.
5. Erstelle 04_Review.
6. Erstelle 05_Output.
7. Erstelle prompts.

Prompt-Dateien:
1. Erstelle prompts/research_lauf.md.
2. Erstelle prompts/source_card.md.
3. Erstelle prompts/claim_card.md.
4. Erstelle prompts/review.md.
5. Erstelle prompts/dossier_update.md.
6. Erstelle prompts/weekly_refresh.md.
7. Erstelle prompts/output_draft.md.

Regeln:
- Trenne Fund, Deutung und Beleg.
- Eine Claim Card enthält eine Aussage.
- Jede Aussage enthält Quelle, Belegstelle, Evidenztyp, Grenze und Status.
- Neue Themen starten in 00_Inbox.
- Ein Lauf schreibt ein Run Log in 04_Review.

Erster Lauf:
1. Lies alle Dateien in 00_Inbox.
2. Erstelle Source Cards in 01_Quellen.
3. Erstelle Claim Cards in 02_Claims.
4. Erstelle Review Notes in 04_Review.
5. Erstelle oder aktualisiere Dossiers in 03_Dossiers.
6. Schreibe offene Aufgaben in 04_Review/run_log.md.

Das System braucht Pflege.

Ein Lauf aktualisiert Quellen, Claims, Grenzen, Gegenpositionen, Dossiers und nächste Fragen.
